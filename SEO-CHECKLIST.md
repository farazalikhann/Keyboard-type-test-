# SEO & AdSense Readiness Checklist

What was implemented in this pass, with file paths, so it's auditable later. Written after the work, not as a promise — everything listed here was built and verified (`npm run build`, `npx tsc --noEmit`, `npx next lint`, and a Playwright pass through every new interactive tool).

## Domain migration

- `public/CNAME` → `keyboardtoolkit.site`
- `next.config.mjs` — root-relative paths by default; the old `/Keyboard-type-test-` basePath only applies if a build explicitly sets `GITHUB_PAGES=true` without `CUSTOM_DOMAIN=true` (kept as a documented fallback, not the default)
- `.github/workflows/deploy.yml` — builds with `CUSTOM_DOMAIN=true`, verifies `out/CNAME` exists as a build step
- `src/lib/site.ts` — single source of truth for `SITE_URL`, `SITE_NAME`, `AUTHOR`, `CONTACT_EMAIL` (placeholder), `ADSENSE_CLIENT` (placeholder), `GOOGLE_SITE_VERIFICATION` (placeholder)
- Verified: `grep -r "Keyboard-type-test-" out/` returns nothing outside `next.config.mjs`'s intentional fallback

## Metadata layer

- `src/app/layout.tsx` — `metadataBase`, title template, OpenGraph, Twitter card, `robots` block, icons, manifest, conditional `verification.google` (only emitted once a real token replaces the placeholder)
- Every route (36 pages) has its own `metadata` export with a unique title and description, and `alternates.canonical` set to an absolute `https://keyboardtoolkit.site/...` URL
- `<html lang="en" dir="ltr">`
- Icons: `public/apple-touch-icon.png`, `public/icon-{16,32,192,512}.png`, `public/og-image.png` — generated by `scripts/generate-icons.js` (a small dependency-free PNG encoder), **not** `next/og`'s `ImageResponse`. That API's bundled font loader throws `Invalid URL` on this machine specifically, because the project path contains a space (`D:\micro saas business\...`) and its internal file-URL construction isn't space-safe. This is an environment bug, not a code defect — see "Known follow-ups" below.
- `public/site.webmanifest` — name, icons, theme/background color matching the dark palette

## Sitemap, robots, crawl control

- `src/app/sitemap.ts` — generated from `TOOL_ROUTES` / `LEGAL_ROUTES` (`src/lib/routes.ts`) and `POSTS` (`src/lib/blog.ts`), not a hand-written array. Adding a tool to the registry or a post to the blog collection puts it in the sitemap automatically.
- `src/app/robots.ts` — allows all crawlers, points to `https://keyboardtoolkit.site/sitemap.xml`
- Verified in `out/`: `sitemap.xml` and `robots.txt` both exist and contain valid, absolute URLs
- `out/404.html` and `out/404/index.html` both exist (Next emits both forms under `trailingSlash: true`; harmless duplication of a noindex page, not a sitemap entry)

## Structured data

- `src/components/seo/JsonLd.tsx` — shared, XSS-safe JSON-LD renderer (escapes `<` so a value can't break out of the `<script>` tag)
- Root layout: sitewide `WebSite` + `Person` (author) schema
- `src/components/seo/ToolSchema.tsx` — `SoftwareApplication` schema (category, `$0` offer, feature list) on all 12 tool pages
- `src/components/seo/Breadcrumbs.tsx` — visible breadcrumb trail + matching `BreadcrumbList`, on every page except home
- `Faq` component emits `FAQPage` schema matched word-for-word to the visible Q&A text
- Blog posts emit `Article` schema (headline, dates, author, image) plus `FAQPage` where the post has an FAQ section
- Nothing here invents ratings, review counts, or citations — none of that appears in the schema or the copy

## Content depth (the actual AdSense-critical part)

- Six legal/trust pages, each specific rather than generic: `/about` (563 words), `/contact`, `/privacy-policy` (733 words, explicitly covers AdSense, the DoubleClick DART cookie, Google Ads Settings opt-out, localStorage, GDPR/CCPA, children's privacy), `/terms`, `/disclaimer`, `/cookie-policy`
- `/blog` — ten original 900–1500 word guides (`src/content/blog/*.ts`), each with a real intro, H2/H3 structure, a takeaways list, and an FAQ block. No filler, no invented statistics or sources.
- Every tool page has 300+ words of genuine explanatory content below the tool (verified — see the word-count table below)

## New tool pages (9 new routes, plus 3 typing-test duration variants)

All reuse existing engines rather than forking them — see commit history for the specific reuse in each case:

- `/typing-test/1-minute`, `/typing-test/3-minute`, `/typing-test/5-minute`
- `/typing-practice` (words / punctuation / numbers / code modes)
- `/wpm-calculator`
- `/cps-test`, `/spacebar-counter` (shared `useCountEngine`)
- `/double-click-test`
- `/key-rollover-test`, `/ghosting-test` (shared `useRolloverTest`)

## Navigation

- Header: grouped "Tools" dropdown (typing / keyboard / mouse) + a "Guides" link, both driven by `lib/routes.ts` / `lib/blog.ts`
- Footer: four columns (Tools, Guides, Legal, About)
- `RelatedTools` (3 links) and `RelatedReading` (2 blog posts) on every tool page
- Breadcrumbs on every non-home page
- Every route is reachable from the home page within two clicks (home → header/footer link → any tool or guide)

## AdSense integration

- `public/ads.txt` with a placeholder publisher ID (replace before going live — see `TODO-MANUAL.md`)
- `src/components/ads/AdsenseLoader.tsx` — loads the AdSense script only when `ADSENSE_ENABLED` (real client ID configured, production build) **and** the visitor has accepted the cookie banner
- `src/components/ads/AdSlot.tsx` — fixed-height container (no CLS), renders a labeled placeholder box until a real client ID is set, a real `<ins class="adsbygoogle">` tag otherwise
- Placement: 2 slots per tool page, both below the interactive area (below results, and in the content section). None sit above the H1, none are adjacent to the typing input, the keyboard grid, or any start/exit test button. Legal pages carry zero ad slots.
- `src/components/consent/ConsentBanner.tsx` — localStorage-based accept/reject banner, blocks the AdSense script until accepted. **This is not a certified CMP** — see `ADSENSE-SUBMISSION.md` and `TODO-MANUAL.md` for what's needed before serving EEA/UK traffic at scale.

## Accessibility

- Exactly one `<h1>` per page (visually hidden on tool pages where the instrument itself is the visual header, present via `sr-only`)
- Landmarks: `header`, `nav` (labeled where more than one exists), `main`, `footer`
- Skip-to-content link in the root layout
- Visible focus ring globally (`:focus-visible` in `globals.css`), unchanged from the original build
- `aria-live="polite"` added to the shared `Readout` component and the typing test's live accuracy/WPM stats
- Contrast fixed: `--fg-muted` was 3.93:1 against `--panel-raised` (dark theme); the light theme's `--signal` was 3.62:1 against its background. Both now clear 4.5:1 against every surface they're used on (see commit `fix(a11y)`). No other token changes — the palette and typography are otherwise untouched.

## Performance

- `next/font` with `display: "swap"`, self-hosted at build time (no third-party font request at runtime, so no Google Fonts preconnect is needed)
- `preconnect` added for `pagead2.googlesyndication.com`
- All ad containers have a fixed reserved height; no image without explicit dimensions is used as content anywhere on the site
- Bundle: shared JS is 87.4 kB. The three biggest contributors are `chunks/fd9d1056-*.js` (53.6 kB — React/React DOM/Next runtime, present on every Next.js App Router site), `chunks/117-*.js` (31.9 kB — Next's router/webpack runtime glue), and the two interactive tool pages themselves (`/typing-test` and `/keyboard-test`, ~7 kB each for their engines). These are baseline Next.js costs, not something addressable without ejecting from the framework.
- WebP/AVIF conversion wasn't applicable — the only raster assets are flat-color generated PNGs (icons, OG card), where PNG is already smaller than WebP would be for that kind of image

## Known follow-ups (not done in this pass, and why)

- **Per-page text OG images.** The current OG card (`public/og-image.png`) is a single shared graphic (no title text) for the whole site, because `next/og`'s `ImageResponse` fails to build in this specific environment (path-with-space bug, described above) and hand-rasterizing text without a font library was out of scope. Once building on a path without spaces (or with `sharp`/`@napi-rs/canvas` added as a dependency), re-introducing `app/opengraph-image.tsx` per route is a clean win.
- **A certified CMP.** `ConsentBanner` is a functional but non-certified consent banner. See `TODO-MANUAL.md`.
- **Lighthouse scores were not run** in this environment (no Chrome/Lighthouse CLI available here) — the performance section above is based on build output and known Next.js/App Router behavior, not a measured score. Run Lighthouse against the live `keyboardtoolkit.site` once DNS is live.
